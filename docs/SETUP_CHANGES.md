# Setup Changes for Transaction Support

## Summary

The `setup` binary has been updated to automatically generate the `transaction_port` field in validator configuration files. This field is **required** for validators to accept transaction submissions via HTTP.

## What Changed

### Before (Old Behavior)
- ❌ `transaction_port` was **NOT** generated by setup
- ❌ You had to manually add `transaction_port` to each validator config
- ❌ Validators would fail to start with the new HTTP server feature

### After (New Behavior)
- ✅ `transaction_port` is **automatically generated** by setup
- ✅ No manual editing of config files needed
- ✅ Validators start successfully with transaction support enabled

## Generated Ports

### Local Deployment
When running `setup generate local --start-port 3000`:

| Validator | P2P Port | Metrics Port | Transaction Port |
|-----------|----------|--------------|------------------|
| 0         | 3000     | 3001         | **8081**         |
| 1         | 3002     | 3003         | **8082**         |
| 2         | 3004     | 3005         | **8083**         |
| 3         | 3006     | 3007         | **8084**         |

The formula: `transaction_port = 8080 + (port - start_port) / 2 + 1`

### Remote Deployment
When running `setup generate remote`:
- All validators use: `transaction_port = 8080`
- (Since each validator is on a different machine, they can all use the same port)

## How to Use

### Full Setup Command

```bash
cd chain

cargo run --release --bin setup -- generate \
  --peers 4 \
  --bootstrappers 1 \
  --worker-threads 3 \
  --log-level info \
  --message-backlog 16384 \
  --mailbox-size 16384 \
  --deque-size 10 \
  --output test \
  local --start-port 3000
```

### Generated Config Example

```yaml
private_key: <generated_key>
share: <generated_share>
polynomial: <generated_polynomial>
port: 3000
metrics_port: 3001
transaction_port: 8081        # ← Automatically generated!
directory: /path/to/storage
worker_threads: 3
log_level: info
allowed_peers: [...]
bootstrappers: [...]
message_backlog: 16384
mailbox_size: 16384
deque_size: 10
indexer: null
```

## Migration Guide

### If You Already Have Config Files

**Option 1: Regenerate (Recommended)**
```bash
cd alto/chain
rm -rf test/
cargo run --release --bin setup -- generate \
  --peers 4 \
  --bootstrappers 1 \
  --worker-threads 3 \
  --log-level info \
  --message-backlog 16384 \
  --mailbox-size 16384 \
  --deque-size 10 \
  --output test \
  local --start-port 3000
```

**Option 2: Manual Addition**
Add `transaction_port` to each existing config file:
```yaml
# Add this line after metrics_port
transaction_port: 8081  # Use 8081, 8082, 8083, 8084 for validators 0-3
```

### If Starting Fresh

Just run the setup command above. The `transaction_port` will be automatically included.


4. **Test transaction submission**:
   ```bash

     --validator http://localhost:8081 \
     --sender-seed 100 \
     --receiver <receiver_hex> \
     --amount 1000
   ```
